# Generate semantic session display names asynchronously

Pi sessions will keep their technical `sessionId` but receive a human-readable Session Display Name derived once from the first expanded user prompt through the Model Policy Registry's `fast` Role. The request runs asynchronously, is guarded by the current session generation, and records a session-scoped attempt marker to avoid retrying across reloads; model request failures fail silently, preserving Pi’s native first-message fallback, while model policy loading or configuration errors are surfaced with `ctx.ui.notify(..., "error")`; explicit user names always win. Forks inherit the current base name and append a six-character lowercase hash of the child `sessionId`, while later resume/reload never re-adds a suffix. This deliberately trades one extra provider request and its prompt privacy cost for stable, scannable names without delaying the user’s first response or introducing a new model configuration surface.
