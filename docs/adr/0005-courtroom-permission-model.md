# 法庭隐喻：三角色权限审查模型

权限系统从"法官+教授（事后分析假阳性）"的二元模型，扩展为法庭隐喻的三角色模型，并引入 JUDGE.md 作为项目级安全规则的单一事实源。

## 三角色

| 角色 | 时机 | 职责 |
|------|------|------|
| **Judge（法官）** | 实时 | 对每个工具调用判 safe/unsafe，综合系统基线规则 + 项目 JUDGE.md |
| **Advocate（辩护人）** | 事后，`/permission-advocate` 手动触发 | 审查假阳性：法官判 unsafe 但用户手动批准 → 输出 allow 规则建议 |
| **Prosecutor（检察官）** | 事后，`/permission-prosecutor` 手动触发 | 审查假阴性：审计全部被放行的记录，用更强模型二次审查 → 输出 deny/检测规则建议 |

Advocate 和 Prosecutor 的输出均直接写入项目根目录的 `JUDGE.md`，而非生成独立报告。JUDGE.md 是持续演进的单一事实源，被注入法官 prompt 末尾作为项目级扩展。

## Considered Options

- **假阳性/假阴性合并为一个工具**：被拒绝。两种审查的信号源不同（假阳性有用户手动批准信号，假阴性需要全量审计），合并会混淆触发条件和输出语义。
- **Prosecutor 只审中低分放行记录（分数阈值）**：被拒绝。高分的危险操作恰好是假阴性最危险的一类——法官越自信地误判，越需要被审。全量审计覆盖面完整。
- **审查结果独立输出为报告**：被拒绝。独立报告会导致规则分散、冲突、过期。统一写入 JUDGE.md 形成持续演进的单一事实源。
- **安全判定分类从"按工具类型"改为"意图链分析"**：接受。原 judge-prompt.md 按工具名分类（只读=安全，破坏性=不安全），对管道注入、heredoc 写入、外部依赖等攻击模式无效。新指标追踪数据/效果的最终落点，而非工具名。

## Consequences

- JUDGE.md 作为项目级文件，随时间累积规则会膨胀。采用"一行一条规则 + 写入前去重"控制体积，不设置过期淘汰（以后再说）。
- 两个审查工具的输出直接修改 JUDGE.md，意味着用户不需要手动搬运规则——但也意味着误操作可能污染 JUDGE.md。
- 对抗性自测（攻击模型生成变种，法官拦截）作为新 prompt 的验证手段；评估指标为精确优先（宁可漏，不误拦）。
