发现：`my-back`、`my-cd-guard`、`my-html`、`my-hud`、`my-permission`、`my-script-guard` 下仍有独立 `scripts/deploy.ts`，目标是旧的 `extensions/my-*` 路径；当前统一流水线使用 `extensions/ly-pi`。另有两份空的 `my-back.json`，以及当前 HTML 模块未读取的 `my-html.json`。

证据：[统一流水线](../../scripts/deploy-all.ts)、[旧 back 部署脚本](../../ly-pi/my-back/scripts/deploy.ts)、[HTML 模块入口](../../ly-pi/my-html/index.ts)。

验收标准：

- [ ] 核实旧脚本和配置的全部引用、实际用途，并记录删除或保留理由。

## 02 — 补齐 verify 与测试隔离

发现：根 `verify` 未执行 `tools/pi-w` 和 `tools/check-docs` 的单元测试，也未执行 `tools/check-docs` 的类型检查。成本记录测试会写入真实的 `~/.pi/costs`，在当前沙箱中触发 `EPERM`。

证据：[根脚本配置](../../package.json)、[成本记录测试](../../ly-pi/my-permission/cost-tracker.test.ts)。

验收标准：

- [ ] 三个 workspace 的必要类型检查和单元测试均纳入统一验收，并保留文档检查。
- [ ] 默认成本路径仍被验证，测试读写使用临时目录或可控替代，不依赖真实用户目录写权限。
- [ ] `bun run verify` 全部通过，不跳过失败测试或削弱现有检查。
