# tool-run-fold — 工具运行折叠为一行摘要

Status: ready-for-agent

## Problem Statement

当前 Pi 会话把每一次工具调用铺成一块独立渲染的工具行。即使 `my-tool-display` 已经压掉了单条行的正文（隐藏 read/grep/find/ls 输出、bash 只留 10 行、diff 只留 24 行），每条工具行仍要支付固定行高：一条分隔空行加上带上下留白的状态色块。已折叠的 read 行占 4 行，折叠的 bash 行占 14 行，折叠的 edit 行接近 28 行。一次普通的 agent run 轻松吃掉几十行。

结果是 user ↔ LLM 的对话节奏被打散：用户发出消息后，屏幕被中间过程填满，最终回答被推远。用户看到的不是「我问了 → 它答了」，而是「我问了 → 一大堆工具执行 → 它答了」。单条工具的紧凑化解决不了这件事，因为问题不在每行的内容，而在于这些行本身占据会话版面。

## Solution

在 `my-tool-display` 内增加**工具运行折叠**：一次 Tool Run（从一条用户消息到该次回答结束之间的全部工具执行过程）在会话里只留下一条 Run Summary Row，例如 `⚙ 12 calls · 1m42s`。详细过程按需展开，展开后与今天完全一致。

折叠采用**完成即收**：Tool Run 进行中，屏幕上只有 Run Summary Row 和 Live Tool Row（正在执行的那条工具行）；每条工具行在自己的执行结束时立即消失，不留下空行。`ctrl+o` 保持 Pi 原生语义作为**唯一的展开入口**（展开所有 run 的所有输出）。

不提供单 run 展开：Pi 仅在 fullscreen 模式上报鼠标（普通模式由终端接管滚屏），而 Pi 的“展开单行”唯一入口就是鼠标点击，因此点击不属于可达的交互面；本功能不接琡点击也不新增快捷键。

工具失败不会被藏掉：失败的工具行同样收起，但 Tool Run 结束时会在该 Run 最后一条 Tool Row 的位置额外显示一条 Run Failure Notice（`⚠ 1 failed · bash: bun test`）。被中断或报错终止的 Tool Run 走同一机制（`⚠ aborted at bash: …`），因此中断不会在屏幕上留下几十行现场。

可见的工具行**保持当前呈现逻辑逐字不变**：同样的状态色块、同样的内外边距、同样的折叠行数规则。折叠只改变哪些行存在，不改变存在行长什么样。

## User Stories

1. As a Pi 用户, I want 一次 Tool Run 在会话里只占一行, so that 我的消息和它的回答在视觉上紧邻，读起来像对话。
2. As a Pi 用户, I want 正在执行的工具行始终可见, so that 长跑任务期间我仍知道 agent 正在做什么。
3. As a Pi 用户, I want 每条工具行在它执行结束时立刻消失, so that 中间过程不会一点点堆满屏幕。
4. As a Pi 用户, I want Run Summary Row 显示调用次数和本次运行的耗时, so that 我不展开也能判断这次运行有多重。
5. As a Pi 用户, I want Run Summary Row 提示可以用 `ctrl+o` 展开, so that 我知道细节还在、怎么拿出来。
6. As a Pi 用户, I want 只看 `ctrl+o` 一个入口就把所有细节拿回来, so that 我不需要记新键位，也不需要鼠标。
7. As a Pi 用户, I want 按 `ctrl+o` 展开所有 run 的所有输出, so that 量级判断和细节查看共用一个我本来就熟的键。
8. As a Pi 用户, I want 折叠与展开完全由 `ctrl+o` 决定、不引入额外的 run 级展开状态, so that 我不会看到“某些行展开、某些行不展开”的混合态。
9. As a Pi 用户, I want 工具失败时仍能直接看到失败信息, so that 紧凑呈现不会掩盖诊断。
10. As a Pi 用户, I want Run Failure Notice 显示失败次数与失败工具的简短定位, so that 我不展开也知道哪里出了问题。
11. As a Pi 用户, I want 被中断或报错终止的 Tool Run 也收起并给出提示, so that 中断不会在会话里留下几十行现场。
12. As a Pi 用户, I want 展开后的工具行与今天完全一致, so that 折叠只是减少版面，不是换了一套我陌生的呈现。
13. As a Pi 用户, I want 助手在过程中写的过渡文字保持原位, so that 叙述线索不丢，收起的只是工具行。
14. As a Pi 用户, I want 恢复历史会话时历史的 Tool Run 也按同一规则折叠, so that 新旧会话的阅读节奏一致。
15. As a Pi 用户, I want 一次运行里 80 条工具调用也能一行带过, so that 极端情况下会话版面不失控。
16. As a Pi 用户, I want 展开时不被行数上限截断, so that 需要全量回看时不需要分次操作。
17. As a Pi 用户, I want 在配置里关掉折叠回到逐条工具行呈现, so that 我可以安全地退回旧行为。
18. As a Pi 用户, I want 配置缺失或字段非法时获得稳定默认, so that 一份坏配置不会让会话变形或启动失败。
19. As a Pi 用户, I want `print` / `rpc` 等非交互模式不受影响, so that 同一份配置在脚本调用中保持安全。
20. As a ly-pi 维护者, I want 折叠逻辑集中在一个可独立测试的核心, so that 行为调整不需要通过渲染层反推。
21. As a ly-pi 维护者, I want 工具的执行、参数与模型上下文完全不变, so that 显示功能不会悄悄改变 agent 的能力。
22. As a ly-pi 维护者, I want 折叠不写入会话文件, so that 「纯展示」这个承诺可审计。
23. As a ly-pi 维护者, I want `/reload` 后不重复注册、不重复监听, so that 多次重载的呈现保持稳定。
24. As a ly-pi 维护者, I want 其他扩展已拥有某个原生工具时不被本功能抢占, so that 多扩展环境不因折叠而改变工具所有权。

## Implementation Decisions

- **归属与边界**：折叠是 `my-tool-display` 的内部能力，不新开模块。它对统一入口的 interface 不变（仍只提供「为七个原生工具注册呈现覆盖」）；展开状态、事件订阅、计时和恢复重建都隐藏在该模块内部。
- **折叠单元**：Tool Run，从一条用户消息开始到该次回答结束（含中间所有 LLM 调用与工具调用）。它不等于 Pi 的 turn，也不按工具类型分组。
- **渲染壳层**：七个被覆盖的原生工具注册从默认壳改为自有壳，以便隐藏行真正做到零高度。可见行由模块自己绘制与当前一致的外框和状态底色，保证观感逐字不变；折叠行渲染为空组件，不占任何行。
- **呈现决定核心**：新增一个不依赖 TUI 的折叠核心，输入是工具执行事件、Tool Run 边界、展开动作与时钟，输出是每条 Tool Row 的呈现（摘要行 / 实时行 / 失败提示行 / 普通行 / 隐藏）以及摘要文案。渲染层只做「决定 → 组件」的翻译，不含折叠规则。
- **摘要行承载**：Run Summary Row 由该 Tool Run 的第一条 Tool Row 承载，因此它出现在过程开始的位置，位于用户消息与最终回答之间。
- **失败提示行承载**：Run Failure Notice 由该 Tool Run 的最后一条 Tool Row 承载，因此它出现在过程结束的位置，紧邻最终回答。
- **摘要文案**：`⚙ <N> calls · <耗时>`，失败时追加 `⚠ <N> failed`，末尾附一个暗色的 `ctrl+o` 展开提示。耗时为本次 Tool Run 的持续时间，格式为可读的分钟秒组合。工具类型分布不进摘要行。
- **折叠状态与交互**：Tool Run 结束时该 run 折叠。折叠与展开完全由 `ctrl+o` 的全局状态决定，不引入 run 级展开状态，也不存在“已展开的 run”需要记住。
- **全局开关**：`ctrl+o` 的全局展开状态就是总开关，为真时所有工具行按现有逻辑呈现，run 级折叠被覆盖。本功能不新增快捷键、不新增命令。
- **失败与中断的判定**：失败来自工具结果本身的错误状态；中断或报错终止来自该次回答的停止原因。两者都走收起路径，只在 Run Failure Notice 的文案上区分。
- **展开上限**：展开不设行数上限；单条工具行的输出仍受现有折叠行数规则约束。
- **恢复会话**：在会话恢复时，模块从会话条目中的 `toolCallId` / `toolName` 顺序重建 Tool Run 边界，使历史工具行按同一规则折叠。展开状态不持久化：恢复后的 run 一律回到默认折叠。
- **配置契约**：在现有配置上新增一个布尔字段（默认启用折叠）。缺失、格式错误或非法值回退默认；字段为 false 时不产生任何折叠行为，回到逐条工具行呈现。配置只在加载或 `/reload` 后生效。
- **非交互降级**：非 TUI 模式下不注册任何依赖 UI 的副作用；折叠核心在无渲染调用时保持静默。
- **生命周期与所有权**：沿用现有的原生工具所有权检查与重载清理；本功能新增的事件订阅与计时状态必须在重载或会话替换时撤销，避免重复注册或残留计时。
- **不改动的部分**：工具执行、参数、提示元数据、取消与输出截断语义、模型上下文、会话文件内容均不变；本功能不写 entry、不发消息、不注册命令。

## Testing Decisions

- **好测试的标准**：测试从工具事件序列、会话条目、配置、主题和交互动作出发，断言用户可见的结果（哪些行存在、摘要行与提示行显示什么、可见行渲染成什么），不触碰内部缓存、私有状态或具体 helper。
- **S1 折叠核心（新增，最高 seam）**：用纯单测覆盖 run 边界识别（含一个 run 内的多个 turn）、完成即收、摘要计数与耗时、失败计数、中断与报错终止、全局开关覆盖。这一层不渲染任何东西。
- **S2 渲染契约（沿用现有 renderer 测试）**：断言折叠行渲染为空、摘要行文案与提示、失败提示行文案、Live Tool Row 的实时输出、以及可见行输出与现有断言逐字一致。视觉复刻的验证落在渲染出的行内容与底色/留白上，而不是「是否看起来一样」。
- **S3 配置（沿用现有 config 测试）**：覆盖新字段的存在、缺失、非法类型、以及关闭折叠后完全不改变呈现。
- **S4 恢复与生命周期（沿用现有所有权/reload 测试并新增恢复夹具）**：用会话条目夹具验证历史 Tool Run 重建后的折叠结果；验证重复初始化与重载后只保留一套订阅与状态，且外部所有者不被抢占。
- **S5 统一入口集成（沿用现有 mock 集成测试）**：确认统一入口仍只注册一次 `my-tool-display`。
- **Prior art**：折叠核心与恢复夹具的行为导向风格参照 `my-diff` 的测试；配置回退参照现有 HUD/config 的临时目录模式；所有权与重载参照现有 `my-tool-display` 测试；统一入口参照现有模块 mock 模式。
- **验收**：按红绿循环实现；完成后运行 `bun run verify`，再执行部署流程与 `/reload`，并在真实 TUI 中人工确认：完成即收、Live Tool Row、`ctrl+o` 总开关、失败提示、中断提示、展开后与旧呈现一致、窄终端不溢出、恢复历史会话的折叠结果。

## Out of Scope

- 隐藏或改写助手在过程中的过渡文字（markdown transformer 路线）
- thinking block 的折叠（Pi 原生 `ctrl+t` 已覆盖）
- run 内再分组（按工具类型、按阶段、按文件）
- 保留最近若干条已完成行、部分展开、按工具类型选择性折叠等附加模式
- 单 run 展开（点击摘要行、快捷键或其他逐 run 入口）
- 展开状态的持久化与跨会话记忆
- 用自定义 entry 承载摘要或提示行
- MCP、第三方扩展工具与自定义工具的折叠
- 修改工具执行、权限、参数、上下文或输出截断语义
- 新增斜杠命令、设置弹窗、快捷键或运行时配置写回
- 非 TUI 模式的渲染
- 折叠核心与 `my-diff` 之间的共享抽取（当前只有一个调用者）

## Further Notes

- 风险级别：Medium。该功能改变用户可见的会话节奏，并触及 renderer 壳层、事件生命周期与会话恢复路径；本规格记录了用户确认的范围与验收基线，实施前应按项目交付护栏记录批准。
- 关键机制前提：Pi 仅在被覆盖工具使用自有壳、且该行内容渲染为空时才会让整行不占高度；默认壳会为每一行保留一个分隔空行，因此「完成即收」无法在默认壳下实现。这是本规格选择自有壳的唯一原因，不是为了改观感。
- 视觉复刻按逐字一致要求验收：可见行的留白、底色与内容必须与现有实现一致，任何观感差异都视为缺陷而不是「顺便优化」。
- 摘要行的展开提示使用 Pi 的键位提示机制，保证用户改键位后提示同步（提示指向 `app.tools.expand`，即 `ctrl+o`）。
- **鼠标约束**：Pi 仅在 `--tui-mode fullscreen` 下上报鼠标（`pi-tui` 只在 alt-screen 实现里打开鼠标上报），普通模式下点击不会进入应用；Pi 里“展开单行”的唯一入口就是这个鼠标点击（`tool-execution.js` 的 `createResultRegion`）。因此本功能以 `ctrl+o` 作为唯一展开入口，不接管点击、不新增快捷键。
- **已知限制**：fullscreen 模式下 Pi 原生的行级点击仍生效。用户点击一条被折叠 run 内的工具行时，只会展开那一行自己的输出（该行所属 run 的其余行仍隐藏），属于拼合后的半展开态；由于折叠与展开完全由 `ctrl+o` 决定，这种状态在收起并重新展开后自动消失。
- 支持目标为当前 Pi 交互式 TUI；旧版 Pi 的兼容层与版本探测不在本期。
